# Firebase data structure

## Current source implementation

The Firebase Web SDK and Firestore client are initialized once in `js/firebase/auth-client.js`. `functions/index.js` contains source-only callable operations for profile synchronization, published course listing, student dashboard reads, assigned teacher course/enrollment reads, free-course enrollment, enrollment-gated lesson access, lesson progress, server-side quiz start/grading, certificate eligibility/issuance/verification, admin course management, assigned teacher lesson/quiz management, and trusted role changes. The Auth creation/deletion triggers remain source-only. **None of these Functions are deployed.** The course, dashboard, quiz, certificate, and admin/teacher pages call the relevant LMS operations, but App Check is not configured and the shared client blocks calls until it is.

Backend documents use `users/{uid}`, `courses/{courseId}`, `courses/{courseId}/lessons/{lessonId}`, `courses/{courseId}/quizzes/{quizId}`, `enrollments/{uid_courseId}`, `progress/{uid_courseId_lessonId}`, `quizAttempts/{attemptId}`, `quizAttemptCounters/{counterId}`, `certificates/{uid_courseId}`, `certificateLookup/{randomCertificateId}`, `certificateVerification/{sha256VerificationCode}`, and `auditLogs/{logId}`. Quiz answer keys and active-attempt grading snapshots are stored only in server-managed documents; Firestore client rules deny these collections. Certificate verification returns limited public fields only.

The source-only profile trigger/callable defines `uid`, `name`, `displayName`, `email`, `emailVerified`, `photoURL`, `role`, `status`, `createdAt`, and `updatedAt`. Role claims—not profile fields—are authoritative. Profile owners can update only the allowed display-name/photo fields under source rules. Passwords remain exclusively in Firebase Authentication.

Repository Firestore rules allow owner profile reads, constrained owner profile updates, and profile listing for a trusted admin claim. They deny every other collection and operation. A live unauthenticated read returned HTTP 403 `PERMISSION_DENIED`; authenticated owner isolation and deployed-rule parity have not been tested. The repository defines indexes in `firestore.indexes.json` for quiz-attempt and progress queries; indexes are not confirmed deployed. Legacy course and assessment sample data are not authoritative and are not automatically seeded into Firestore.

## Implemented backend document contract (source only; not deployed)

| Path | Purpose and core fields | Intended access after implementation |
| --- | --- | --- |
| `users/{uid}` | Auth-linked profile: `uid`, `name`, `displayName`, `email`, `emailVerified`, `photoURL`, `status`, `createdAt`, `updatedAt`. `name` and `displayName` are synchronized for compatibility with the current profile UI/rules. | Owner reads their own profile and updates only explicitly allowed profile fields. Admin claim can manage profiles through trusted server code. Roles and account status are never client-writable. |
| `courses/{courseId}` | Course metadata: title, slug, description, category, level, duration, instructorId, thumbnail, status (`draft`, `published`, `archived`), price, currency, teacherIds, requiredQuizIds, timestamps. | Public callable lists published metadata. Admin callable creates/updates/archives; assigned teachers manage limited lessons/quizzes. Firestore client rules deny direct access. |
| `courses/{courseId}/lessons/{lessonId}` | Lesson content: courseId, title, description, content, HTTPS videoUrl, order, duration, status, timestamps. | Callable returns published lessons only to enrolled students; assigned teacher/admin manages through authorized callable. Firestore client rules deny direct access. |
| `courses/{courseId}/quizzes/{quizId}` | Quiz metadata, question text/options, answer indexes, passPercentage, maxAttempts, durationSeconds, status, timestamps. | Enrolled learner receives text/options without answer keys through quiz start. Trusted callable grades using a server-side attempt snapshot. Direct client reads/writes are denied. |
| `enrollments/{uid_courseId}` | Enrollment association: studentId, courseId, status, enrolledAt, completedAt, timestamps. Deterministic ID makes enrollment idempotent. | Callable derives `studentId` from Auth. Free courses can enroll; paid courses fail closed while payments are unavailable. Direct client access is denied. |
| `progress/{uid_courseId_lessonId}` | Per-user lesson progress: studentId, courseId, lessonId, acknowledged, acknowledgedAt, updatedAt. | Authenticated callable checks ownership through Auth UID, active enrollment, and published lesson. Direct client access is denied. Lesson progress is learner-acknowledged, not proof of engagement. |
| `quizAttempts/{attemptId}` | Student submission: quizId, studentId, answers, status, server-calculated score/percentage/pass, timestamps, expiry, private gradingSnapshot. | Callable derives student UID, enforces attempt ownership/time/limits, hides answer keys, and calculates results. Direct client access is denied. |
| `quizAttemptCounters/{counterId}` | Transactional per-student/course/quiz attempt count, keyed by a hash of the identity/course/quiz tuple. | Callable-only transaction state serializes starts so concurrent requests cannot exceed the configured attempt limit. Direct client access is denied. |
| `certificates/{uid_courseId}` | Issued record: random certificateId, private verification hash, studentId/name, courseId/name, status, issuedAt. | Callable issues only after every published lesson is learner-acknowledged and required quizzes have server-passed attempts for their current versions. Lesson acknowledgements are self-reported, not proof of engagement. Direct client access is denied. |
| `certificateLookup/{randomCertificateId}` | Public certificate ID to internal certificate document mapping. | Callable-only lookup; Firestore clients are denied. |
| `certificateVerification/{sha256VerificationCode}` | Hash of a random verification code to internal certificate document mapping. | Callable-only lookup; plaintext verification codes are returned only once at issuance and are not stored. |
| `auditLogs/{logId}` | Admin/teacher operation event: action, actor UID, target ID, limited details, server timestamp. | Trusted backend writes. Firestore clients are denied. |
| `reviews/{reviewId}` | Course feedback: studentId, courseId, rating, comment, moderation status, timestamps. | Enrolled student creates/edits their own review; admin moderates. Students cannot set moderation status or edit another review. |
| `articles/{articleId}` | Educational content: title, slug, excerpt, content, authorId, status, publishedAt, timestamps. | Public reads published articles; admin manages; teacher access requires explicit assignment/authorization. |
| `announcements/{announcementId}` | Platform/course notice: title, message, status, createdAt, expiresAt, createdBy, optional audience/courseId. | Public reads only currently published announcements; trusted admin manages. |
| `users/{uid}/notifications/{notificationId}` | User-specific notification: userId, title, message, type, read, createdAt. | Owner reads and marks their own notification read. Trusted code creates notifications. |
| `contactMessages/{messageId}` | Contact submission: name, email, subject, message, status, createdAt. | Client cannot read or write directly. A validated/rate-limited trusted endpoint creates messages; authorized admin processes them. |

### Authorization and schema notes

- Only Firebase Authentication credentials authenticate a user. Privileged callable access requires its signed token role to match both the current Firebase Auth custom claim and the server-maintained `users/{uid}.role` profile field. Firestore admin rules also require the signed admin claim and matching server-maintained profile role, limiting stale-token access after role changes. A client-written `users/{uid}.role` never grants access.
- The source-only Auth trigger would default public signups to the `student` custom claim. It is not deployed; no role should be assumed for new accounts. Elevating to `teacher` or `admin` must remain a trusted-operator/Admin-SDK action outside frontend JavaScript.
- Firestore rules are not filters. List queries must be constrained so every returned document satisfies the rule; collection-group queries require separate review and tests.
- All LMS callable implementations and indexes in this document are source-only and require Node.js 22. Emulator/security integration testing and deployment remain outstanding. Firebase Functions deployment was reported to require Blaze; billing remains disabled.
- Server-only answer keys, scoring, contact intake, certificate issuance/verification, role changes, and audit history must use trusted server code. Avoid direct student writes for any state that affects awards or authorization.
- Rules must validate required fields, types, allowed field changes, ownership, lifecycle transitions, and parent-course assignment. Deny unknown collections and document paths by default.
- The configured composite indexes cover quiz attempt limits, learner progress, and certificate eligibility queries; deploy and validate their build state before enabling the workflows.

## Activation gate

The database is enabled, but the broader design is source-only and has not been deployed or exercised against an emulator. The available JDK is Java 17; the current emulator setup requires Java 21 or newer. No rules, indexes, or Functions deployment was performed. Do not treat these callable operations as production features until emulator tests, review, and an approved deployment to the intended project are complete.
